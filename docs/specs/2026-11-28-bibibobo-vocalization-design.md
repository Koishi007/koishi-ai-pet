# 语音输出改用 bibibobo 方案

> 把逐字发声的波形从「正弦叠加」换成「polyBLEP 锯齿波 + 双带通共振峰」，取自开源项目 bibibobo（MIT）。音色从电子提示音变为能分辨口型的小人说话声，播放通道、配置面与接入点不变。

## §0 与前一版的关系

[2026-11-27-vocalization-design.md](2026-11-27-vocalization-design.md) 确定了「波形合成而非 TTS」这条路线，以及播放通道、线程模型、配置面与打字机联动。这次只替换其中的合成器，其余部分沿用。

| 项 | 前一版 | 本版 |
|---|---|---|
| 合成器 | 基频 + 两条谐波的正弦叠加 | polyBLEP 锯齿波经两级带通共振峰 |
| 音节参数 | 基频 Hz、时长、是否发声 | 音阶级数 MIDI、时长、口型序号、是否发声 |
| 音色可辨识度 | 只有音高差异 | 音高 + 口型（元音）两个维度 |
| 语气 | 无 | 标点决定整句升降与句尾滑音 |
| 播放通道、配置键、接入点 | - | 不变 |

## §2 上游做法

五步，全部在 `bibibobo.js` 的 `synth()` 里：

| 步骤 | 上游实现 |
|---|---|
| 声源 | 一条 polyBLEP 抗混叠锯齿波，最普通的电子音 |
| 口型 | 两个状态变量滤波器取带通，中心频率是一对共振峰；五种口型各一对 Hz 值 |
| 分字 | 正则切分：一个汉字算一声，一串英文或数字算一声 |
| 定音 | 每个字过一遍小哈希，取模选音阶里的音高，同时选口型序号 |
| 语气 | 问号句尾上扬 5 个半音，感叹号整句升 3 个半音，省略号整句降 3 个半音且句尾下滑 4 个半音 |

音高用哈希而不是随机数，同一个字永远是同一声。这一点与前一版一致，前一版已用码点哈希。

## §3 采纳与调整

### §3.1 采纳的部分

| 上游设计 | 采纳理由 |
|---|---|
| 锯齿波做声源 | 谐波丰富，经带通滤波后才有共振峰可言；正弦叠加的谐波固定，滤波只会削掉而不是塑造 |
| 双带通做口型 | 人耳分辨元音主要靠前两个共振峰，两个数就能拉开听感差异，成本极低 |
| 音高由哈希决定 | 同一角色重复说同一句时听感一致，这是可辨识度的前提 |
| 标点管语气 | 句读本来就在 `syllable.split` 里切出来了，把语气挂上去不需要新增配置 |

### §3.2 需要调整的部分

| 上游做法 | 本项目调整 | 理由 |
|---|---|---|
| 44.1 kHz 采样率 | 22.05 kHz | 播放通道已固定 22.05 kHz，改采样率要连带改 `AudioOut` 的 `QAudioFormat`；共振峰上限 2600 Hz 乘 1.25 倍后仍远低于 11 kHz 奈奎斯特频率，降采样不损失信息 |
| 逐样本递推滤波 | 截断冲激响应做卷积 | 逐样本 Python 循环实测 4.91 ms/音节，是现状 1.4 ms 的 3.5 倍；卷积 512 抽头后降到 0.38 ms，波形与递推的最大差 0.0031 |
| 音高直接取 MIDI 音阶 | MIDI 音阶再叠加音区偏移 | 音区偏移作为用户可选项保留，配置键不废弃 |
| 固定 5 ms 起音、25 ms 收尾 | 起音按 1.5 ms 固定，收尾按时长比例取 40% | 前一版音节时长被钳在 30~60 ms，上游的 25 ms 收尾会吃掉 79% 的音节，音节间没有稳定段 |
| 每句之间 0.22 s 静默 | 沿用现有停顿音节 | 逐字发声场景下停顿来自标点，不需要额外句间隔 |
| 整句一次合成 | 逐字合成 | 与打字机同步，流式台词收齐前无法整句合成，理由同前一版 §4.7 |

### §3.3 不采纳的部分

| 上游做法 | 不采纳理由 |
|---|---|
| 软限幅 `tanh(x * 2.4)` | 逐字发声时每个音节独立限幅，会把弱音节抬成与强音节同响度，句子的轻重消失。改为整批归一化后乘音量，与前一版一致 |
| 两档内置声线 `fish` / `lumo` | 音区已由预设覆盖；口型与共振峰倍率作为角色音色常量写在代码里，等有第二个角色时再抽成表 |
| `toWav()` 与 WAV 封装 | 播放通道直接吃 int16 PCM，不需要文件容器 |
| 浏览器播放与 `index.html` | 与桌宠无关 |

## §4 设计

### §4.1 分层

模块划分与前一版一致，只改 `waveform.py` 的内部实现：

| 模块 | 职责 | 依赖 | 变化 |
|---|---|---|---|
| `pet/voice/syllable.py` | 文字切分与音高分配 | 仅标准库 | 音节参数改为 MIDI 音阶级数与口型序号 |
| `pet/voice/waveform.py` | 音节 → PCM | numpy | 换成锯齿波 + 双带通 |
| `pet/ui/audio/audio_out.py` | 播放通道 | PySide6 | 不变 |
| `pet/ui/audio/vocalizer.py` | 发声门面 | 上述三者 | 不变 |

`ARCH005` 的约束不变：`syllable.py` 与 `waveform.py` 不得顶层 import Qt。

### §4.2 音节参数

```python
@dataclass(frozen=True)
class Syllable:
    degree: int       # MIDI 音高
    duration: float   # 秒
    vowel: int        # 口型序号，索引进 VOWELS
    voiced: bool      # False 表示停顿，只占时间不发声
```

`pitch: float` 换成 `degree: int`：上游的音高来源是音阶的表索引，保持整数级数才能在 §4.3 里叠加预设偏移而不产生非整数 MIDI 音高。口型 `vowel` 由同一个哈希的低位给出，与音高同源，因此同一个字的口型也固定。

### §4.3 音高与预设

上游每个角色是一组 MIDI 音阶，音高 = `scale[hash % len(scale)]`。本项目改为「固定音阶 + 音区偏移」，只保留两档：

| 预设 id | 音区偏移（半音） | MIDI 音阶 | 基频范围 | f0 < F1 达标率 |
|---|---|---|---|---|
| `deep` | -14 | 48 51 53 55 58 | 131~233 Hz | 100% |
| `soft` | -7 | 55 58 60 62 65 | 196~349 Hz，默认 | 96%，仅 vowel4 的最高音超出 |

基准音阶取 D4 F4 G4 A4 C5，即 D 小调五声：不含半音，连读不刺耳，与上游 `fish` 的 E5 G5 A5 B5 C6 同一构造。

两档的取值依据：基频必须低于口型的第一共振峰，否则激励谐波落在共振峰之外，带通滤波器选不到基频，口型失效，只剩刺耳的锯齿高频。`soft` 的 96% 达标率中，仅 vowel4 的最高音 349 Hz 略高于其 F1=300 Hz。声乐研究把 f0 > F1 视为需要专门调谐补偿的问题，见 §8。

预设表仍放在 `syllable.py`，只含 id、偏移与音阶：

```python
@dataclass(frozen=True)
class VoicePreset:
    id: str
    shift: int
    scale: tuple[int, ...]

PRESETS: dict[str, VoicePreset] = { ... }
DEFAULT_PRESET = "soft"
```

`pet/config.py` 的 `enum` 继续从 `PRESETS` 派生，不手写第二份。

### §4.4 波形合成

`waveform.py` 的入口沿用前一版签名：

```python
def render(syllables: Sequence[Syllable], preset: str, volume: float) -> bytes:
    """音节序列 → 22.05 kHz 单声道 int16 PCM。"""
```

单个音节的管线：

```text
MIDI 音高 + 音区偏移 + 字头滑音 → 频率
        ↓
   polyBLEP 锯齿波
        ↓
   两个带通（共振峰 f1、f2）→ f1 输出 + 0.7 × f2 输出
        ↓
   包络（1.5 ms 起音 + 时长 40% 收尾）
```

**抗混叠**：锯齿波在相位翻转处用一个二次多项式做 polyBLEP 修正，与上游 `saw()` 同一算法。不做修正时锯齿的谐波会折叠到可听频段，产生金属噪声。实测非谐波能量占 200~11000 Hz 总量的比例：

| 基频 | 纯锯齿 | polyBLEP |
|---|---|---|
| 300 Hz | 22.6% | 2.5% |
| 700 Hz | 42.2% | 3.3% |
| 987 Hz | 55.1% | 4.2% |
| 1400 Hz | 57.2% | 5.8% |

基频越高折叠越严重，因此修正是必需的而不是可选的润色。

**滤波器**：上游用状态变量滤波器取带通输出，品质因数固定 4 与 5。本项目改为预计算冲激响应后做卷积，冲激响应按 `(中心频率, 品质因数, 抽头数)` 缓存，同一口型在整场会话里只算一次。

**抽头数**：实测与逐样本递推的波形差：

| 抽头数 | 与递推的最大差 |
|---|---|
| 128 | 0.414 |
| 256 | 0.081 |
| 512 | 0.0031 |
| 1024 | 0.0000 |

取 512。冲激响应衰减到 1e-3 所需的抽头数随中心频率上升而下降：300 Hz 品质因数 4 需 407 抽头（18.5 ms），800 Hz 需 179，2600 Hz 品质因数 5 只需 85。512 覆盖全部共振峰组合。

**电平**：整批音节拼接后统一归一化，再乘音量，与前一版一致。不采用上游的逐音节软限幅，理由见 §3.3。

### §4.5 语气

上游按句切分后给每句套一条语气规则。本项目逐字合成，没有「整句」这个对象：气泡每显示一个字就调一次 `Vocalizer.speak(char)`，因此语气由 `Vocalizer` 跨字符累积，见 §4.7。

规则本身照搬上游，只把「句」换成「段」：

| 触发 | 效果 | 作用范围 |
|---|---|---|
| 段内有 `！` 或 `!` | 所有音节升 3 个半音 | 整段 |
| 段内有 `……` 或 `...` | 所有音节降 3 个半音 | 整段 |
| 段尾是 `？` 或 `?` | 末个音节再升 5 个半音，且加滑音 | 末音节 |
| 段尾是省略号 | 末个音节再降 4 个半音 | 末音节 |

「段」的边界是一次流式台词，从 `speak_stream` 到 `_finish_stream`。语气只对标记出现之后的音节生效：文字逐字流进来，`！` 之前的音节已经合成并播出，无法回头更改。这与上游的整句合成不同，是本方案的已知偏差，见 §8。

### §4.6 节奏

音节固定 110 ms，停顿 220 ms，与打字间隔无关。打字间隔 60 ms，快于音节，因此语音会落后于文字。

110 ms 的下限由两个约束决定：

| 约束 | 数据 |
|---|---|
| 速率需接近人类语音 | 110 ms/字合 545 字/分；人类中文为 180~260 字/分，此处偏快但仍在可辨范围 |
| 口型必须来得及成型 | 300 Hz 共振峰需 18.5 ms 建立，音节扣掉起音与收尾后剩下的稳定段必须远大于它 |

不同音节时长的可用稳定段：

| 音节时长 | 稳定段 | 扣除共振峰建立（18.5 ms） |
|---|---|---|
| 31.5 ms | 17.4 ms | 负值，口型未成型 |
| 110 ms | 64.5 ms | 46 ms 可辨 |

上游的每字间隔是 130 ms（发声 104 ms），110 ms 与之接近。打字机取 60 ms，滞后量见下表：

| 台词字数 | 文字走完 | 语音走完 | 滞后 |
|---|---|---|---|
| 9 | 540 ms | 990 ms | 450 ms |
| 14 | 840 ms | 1540 ms | 700 ms |
| 15（含标点） | 900 ms | 2090 ms | 1190 ms |

滞后随字数线性增长。气泡本身显示 5 秒，句末的滞后落在气泡仍可见的区间内。积压上限 3.0 秒对应约 60 字不间断台词，覆盖典型台词长度。

包络取值见 §3.2：起音 1.5 ms，收尾取时长的 40%。上游的固定 25 ms 收尾在长音节上占比过小、在短音节上占比过大，按时长派生才在两档之间保持稳定。

实测两种包络的响度：

| 包络 | 峰值 | RMS |
|---|---|---|
| 上游 5 ms / 25 ms | 2.81 | 0.681 |
| 本设计 1.5 ms / 40% | 3.00 | 0.928 |

上游式包络让每个音节的有效能量明显偏低，这在高采样率长音节里无所谓，在短音节里会让声音发虚。

### §4.7 逐字发声下的语气累积

`Vocalizer.speak` 每次收到一个字符，因此只保留需要跨字符的状态：

| 字段 | 作用 |
|---|---|
| `_shift` | 当前段的半音偏移，见到 `！` 置 3，见到省略号置 -3 |
| `_applied` | 最近一次实际用于合成的 `Tone`，供用例断言 |

`_shift` 只影响标记之后到达的音节，见 §4.5 的偏差说明。句尾滑音不跨字符保留：问号单独到达时它自己是停顿音节，无处可落，记下来会污染下一个字。整段文本一次送来时，`syllable.split` 自己判定语气，滑音正常落在末个发声音节上。

状态在 `discard_stream()` / `flush_pending()` / `_hide_bubble()` 调用的 `clear()` 里复位，与音节队列的作废时机一致。没有这一层时，一句感叹号会让后续所有发言都保持升 3 个半音。

`vowel` 与 `degree` 都由字符哈希给出，不需要跨字符状态。

## §5 实测数据

Windows 10、Python 3.11.9、numpy 2.4.6、Realtek 板载输出。本版数字由产物代码测得，冲激响应缓存预热后取多次运行的中位数：

| 项目 | 前一版（正弦叠加） | 本版（锯齿 + 共振峰） |
|---|---|---|
| 合成一个音节（110 ms） | 1.4 ms | 0.95 ms |
| 合成 20 字整句 | 46 ms | 14 ms |
| 单音节 PCM | 2424 字节 | 4850 字节（110 ms） |
| 首次调用（含冲激响应计算） | - | 约 1 ms，每个共振峰只付一次 |

音节从 31.5 ms 延长到 110 ms 后，合成开销按长度等比上升，仍低于主线程可感知的阈值。整句 14 ms 对 2.2 秒的播放时长可以忽略。

逐样本递推版本 4.91 ms/音节，比卷积版慢 5 倍，是改用卷积的原因。

五种口型的音色差异用频谱质心衡量，同一音高、同一时长下取值 1295~2798 Hz，彼此不重合。这是音高之外的第二维听感差异，也是本方案相对正弦叠加的主要收益。

## §7 测试计划

| 用例 | 断言点 |
|---|---|
| 音高稳定性 | 同一字符在同一预设下多次调用返回相同 MIDI 级数 |
| 音高归属 | 返回的级数落在该预设偏移后的音阶内，两档之间的差值等于偏移差 |
| 口型稳定性 | 同一字符口型固定且在 0~4 内；不同字符口型不全相同 |
| 抗混叠 | 非谐波能量占比低于 10%，且同基频纯锯齿高于 30% |
| 双共振峰 | 两个共振峰中心频率处的能量都高于两峰中点处 |
| 抽头精度 | 512 抽头与 1024 抽头的输出差异小于 1e-2 |
| 语气 | 感叹号整段升 3；问号末字升 5；省略号整段降 3、末字降 4 |
| 语气累积 | 整段升降跨字符保留；滑音不泄漏到下一个字；`clear()` 复位 |
| PCM 格式 | 长度等于时长的采样数×2；int16 小端；峰值不超过满量程 |
| 音量 | 0 时全零；翻倍时峰值同比变化 |
| 开关关闭 | 关闭状态下不产生 PCM |

断言按契约标识写：MIDI 级数、口型序号、字节长度、能量比。不断言具体采样值，也不断言听感。

## §8 风险

- **语音滞后于文字**。打字 60 ms/字、音节 110 ms/字，每字净积压 50 ms，滞后随字数线性增长（15 字约 1.2 秒）。气泡显示 5 秒，滞后落在可见区间内，但长台词的后半段会让声音明显落后于已显示的文字。缓解方式是提高打字间隔或缩短音节，两者都会牺牲各自的观感。
- **积压上限 3.0 秒，超出时静默跳过音节**。正常路径不触发，只在音频设备停滞或超长台词时命中。上限从 0.5 秒上调两次，0.5 秒在 60 ms 打字下只够约 4 个字。
- **共振峰依赖采样率**。滤波器的 `f = 2 sin(π fc / fs)` 与采样率绑定，改采样率必须重算冲激响应缓存。缓存键含中心频率，采样率是模块常量，改动时缓存自然失效，但没有断言守住这一点。
- **抽头数是听感与开销的折中**。512 抽头相对 1024 的最大波形差 0.0031，听感未验证。提到 1024 会让卷积成本翻倍，20 字整句从 4.0 ms 增到约 8 ms；该外推未单独计时。
- **语气只对标记之后的音节生效**。上游整句合成，感叹号能让整句升调；本项目逐字流式，`！` 到达时前面的音节已经播出。句首气声、句中标点引起的升降都来不及作用。需要完全对齐上游时只能改为整句预合成，但那会牺牲与打字机的同步。
- **逐字送来的句尾滑音不生效**。问号到达时它自己是停顿音节，前面那个发声的音节已经合成完毕。整段文本一次送来时行为与上游一致，逐字流式下无解。
- **语气只看标点，不看语义**。反讽、疑问语气词（「吗」「呢」）都不识别。缓解手段是后续把语气词表加进 `syllable`，接口已把语气与音节分开，改动局部。
- **口型与音高同源**。两者都取自同一哈希，不同字可能落到同一音高与同一口型。实测五声音阶配五种口型，同句内重复仍在可接受范围，未做统计。
- **许可义务**。MIT 要求保留版权与许可全文，`LICENSES/bibibobo-MIT.txt` 必须随发行包一起分发；打包脚本若只收 `pet/` 会漏掉它。
