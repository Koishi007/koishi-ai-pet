# 0008 参考文档由代码生成并在 CI 校验

- 状态：已采纳
- 相关代码：`scripts/gen_docs.py`、`tests/test_docs.py`、`.github/workflows/tests.yml`

## 背景

贡献者反馈「项目没有文档，了解内部只能读代码」。文档失效的主因是**写了之后与代码漂移**：
配置项加了没人更新表格、动作参数改了文档还是旧的、提示词块挪了位置文档里的描述就错了。

## 决定

把文档分成两类，分别用不同手段维护：

| 类型 | 内容 | 维护方式 |
|---|---|---|
| **机械事实** | 配置项、动作表、内置工具、粒子特效、提示词块、模块清单 | `scripts/gen_docs.py` 从代码生成（运行时导入 + AST 静态解析），CI 跑 `--check`，不一致即失败 |
| **形状与取舍** | 架构、术语、子系统深入、发布与排障、ADR | 手写；用测试保证覆盖率（每个包都在架构文档里、相对链接有效、索引完整） |

配套约定：

- 生成物头部标「请勿手工编辑」，且**不含时间戳与版本号** - 内容只由代码决定，否则 `--check` 永远判定为不一致；
- 生成器**强制**把 `APPDATA` / `XDG_CONFIG_HOME` 指向空临时目录（不能用 `setdefault`），
  否则开发者本机 `settings.json` 的自定义值会被写进文档，别人机器上必然判定为不一致；
- 参考文档按**默认配置**渲染，需要区分的地方在正文里注明。

## 后果

- 表格类文档不会漂移，改代码后忘记更新文档会直接红灯；
- 代价：改配置/动作/工具/特效/提示词块后要跑一次 `python scripts/gen_docs.py`（PR 模板已列自检项）；
- 手写文档仍会与代码脱节，它靠 review 与覆盖率测试兜底，不靠自动校验。
