# 0017 语音合成改用 bibibobo 的共振峰方案

- 状态：已采纳
- 相关代码：`pet/voice/waveform.py`、`pet/voice/syllable.py`、`pet/ui/audio/vocalizer.py`
- 相关文档：[语音输出改用 bibibobo 方案](../specs/2026-11-28-bibibobo-vocalization-design.md)、
  [语音输出设计](../specs/2026-11-27-vocalization-design.md)

## 背景

[0016](0016-waveform-vocalization.md) 定下了「波形合成而非 TTS」的路线，合成器用基频加两条谐波的
正弦叠加。这条路线本身成立，但正弦叠加的音色只有一个维度：音高。每个字之间除了高低没有别的
区别，听感接近电子提示音，与「小人说话」的预期有距离。

上游开源项目 bibibobo（MIT，`https://github.com/hakihakii/bibibobo`）用同一类方法做出了明显的
口语感：声源是一条 polyBLEP 抗混叠锯齿波，经两个带通滤波器塑形，共振峰决定口型，音高由字符
哈希决定。它面向浏览器与整句合成，不能直接照搬，但算法可移植。

## 决定

- 声源改为 polyBLEP 锯齿波，经两级状态变量滤波器取带通，两级输出按 1 : 0.7 混合。口型是
  一对共振峰频率，五种口型覆盖常见元音。
- 采样率保持 22.05 kHz，不改播放通道的 `QAudioFormat`。共振峰上限 2600 Hz 乘共振峰倍率后仍
  远低于 11 kHz 奈奎斯特频率，降采样不损失信息。
- 滤波器不用上游的逐样本递推，改为预计算冲激响应后卷积。递推实测 4.91 ms/音节，是原实现的
  3.5 倍；卷积 512 抽头后 0.38 ms，与递推的波形最大差 0.0031。
- 音高从「基频 Hz」改为「MIDI 级数 + 预设偏移」。预设取 `deep` / `soft` 两档，配置键与默认值不变；
  基准音阶取 D 小调五声，音高仍由字符哈希决定。
- 包络改为 1.5 ms 起音加时长 40% 收尾。上游固定 5 ms / 25 ms，在 31.5 ms 的音节上收尾占 79%，
  稳定段几乎消失。
- 电平沿用整批归一化后乘音量，不采用上游的逐音节软限幅，避免弱音节被抬到与强音节同响度。
- 标点决定语气：感叹号整段升 3 个半音，省略号整段降 3 个半音，问号末字升 5 个半音并加滑音，
  省略号末字降 4 个半音。逐字发声下语气状态在 `Vocalizer` 里跨字符累积，段落结束时清零。

## 后果

- 收益：音色从「电子提示音」变为可分辨口型的小声音节，音高与口型两个维度让人声更像在说话。
- 收益：合成比原实现更快，0.38 ms/音节对 1.4 ms，20 字整句从 46 ms 降到 7.5 ms。
- 代价：需要履行 MIT 的署名义务，`LICENSES/bibibobo-MIT.txt` 收录上游许可全文，模块 docstring
  写明出处与改动点。本项目是 GPL-3.0-only，两者兼容，但发行包必须带上该文件。
- 代价：滤波器参数与采样率绑定，改采样率要重算冲激响应缓存。
- 约束：`syllable.py` 与 `waveform.py` 仍不得顶层 import Qt，由 `ARCH005` 守住。
- 约束：逐字流式下句尾滑音无法生效，问号到达时它前面的音节已经合成完毕；整段一次送来时行为与上游一致。
- 未验证：512 抽头的听感是否足够干净；未做盲听；macOS 与 Linux 未测。语气规则只认标点，不认疑问语气词。
